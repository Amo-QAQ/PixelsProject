1. **缩放**：4x 最近邻放大（禁止平滑 / 插值）

* `预览XX.png` —— 静态帧（4x）

1. **流程红线**：**必须先对比静态帧与 Tiled 官方渲染一致，再渲染动图**（用户明确要求）

## 四、排障手册（问题 → 根因 → 方案）

### 4.1 瓦片错位（角色 / 灌木整体偏移 32px）—— 最重要

**现象**：导出图里角色、灌木比 Tiled 编辑器里显示的位置偏下 / 偏上。

**根因**：Tiled 渲染 tile layer 的瓦片采用**底边贴格底**对齐，不是左上对齐：



```
py = row \* TILE\_H + TILE\_H - tile\_h      # 底边贴格底

px = col \* TILE\_W                        # 水平仍是左上
```



* 16×16 瓦片：两种对齐等价，无差别

* **48×48 角色、32×32 灌木**：必须用底边对齐，否则整体偏 32px

* collection（如 stone\_01）内实际 16×16 的图像：左上对齐即可

**验证方法**：构造单瓦片最小 tmx，用 tmxrasterizer 渲染后与 spritesheet 模板匹配（min diff = 0 的对齐方式即正确答案）。

### 4.2 半透明边缘颜色变浅（灌木底部发浅）

**现象**：灌木 / 角色底部半透明边缘像素颜色比 Tiled 浅。

**根因**：PIL 的 `canvas.paste(img, pos, img)` 对 alpha 通道计算有缺陷（mask 二次混合），导致半透明像素 alpha 偏小、颜色失真。

**方案**：改用逐瓦片 `Image.alpha_composite(canvas, overlay)` 合成（与 Tiled/Qt 标准混合一致）。

**教训**：`paste` 带 mask 只适用于 "直接覆盖" 场景，涉及半透明合成一律用 `alpha_composite`。

### 4.3 同层大瓦片重叠区丢失边缘（竖排角色与横排角色交错处）

**现象**：同一图层内相邻角色重叠区域边缘缺失 / 错色。

**根因**：角色 48×48 覆盖 3×3 格，同层瓦片重叠时 Tiled 做 alpha 混合；直接 paste 覆盖会吃掉下层边缘。

**方案**：渲染时**逐瓦片**做 `alpha_composite`（每块瓦片先放上透明 overlay 再合成），保证重叠区正确混合。

### 4.4 对比差异排除动画帧干扰



* `tmxrasterizer` 默认渲染**动画第 0 帧**，作为参考基准

* GIF 动画也是从第 0 帧开始循环（正确行为）

* 逐像素对比时只用**第 0 帧**；第 1\~N 帧差异属正常动画推进

* 若静态帧第 0 帧差异为 0，动图即为正确

### 4.5 GIF 颜色偏移 ±30（勿误判）

**现象**：GIF 对比 PNG 参考图有颜色偏差。

**原因**：GIF 格式限制 256 色调色板，量化必然产生 ±30 左右色差。

**方案**：对比差异时**用 PNG 静态帧**（排除量化干扰），GIF 本身的色差属正常，肉眼不可见即可。

### 4.6 tmx 文件编码导致渲染器不认



* `.tmx` 必须用 **UTF-8 with BOM (utf-8-sig)** + `\n` 换行写入，tmxrasterizer 才接受

* `<data>` 的 CSV 末尾**不能有多余悬空逗号**

## 十、可视化导出工具（网页版，2026-09-17 新增）

- `GIF导出工具.html` —— 界面
- `启动GIF工具.bat` —— **双击它启动**（自动开浏览器 http://127.0.0.1:8765）

**功能**：

- 背景色：**浅蓝（默认，商店规格）/ 纯白 / 透明**（透明为可选，GIF 透明保存已修：P 模式 255 色 + 透明索引 255）

- 图层列表现在**包含对象层**，右侧带「对象」标签（如预览01 的 `植物`/`角色`）
- 预览与导出均渲染图块对象（带 gid 的对象）；纯矩形/碰撞框对象不渲染（跳过）
- 图层隐藏按**索引**（预览01 存在同名层，按名字会冲突）：瓦片层 `植物`(#8) 与对象层 `植物`(#11) 可独立开关

**Tiled 图块对象渲染规则（重要，已与官方逐像素验证）**：
1. **底部对齐**：对象 y 是瓦片的**底边**，顶边 = y − 对象高度（不是左上角贴！）——这是此前"所有植物/角色整体偏 16px、颜色全变"的根因
2. **按对象宽高缩放瓦片**：对象 w/h ≠ 瓦片原尺寸时，瓦片 NEAREST 缩放到对象宽高（预览01 有 32×32、16×48 等对象）
3. **位置四舍五入用 half-up**：`int(x + 0.5)`，不能用 Python `round()`（银行家舍入，round(172.5)=172 与官方 173 不符）
4. **对象层内绘制顺序 = topdown（关键！2026-09-17 新修）**：Tiled 对象层默认 `draworder=topdown`，即**按对象 y 坐标升序绘制**（y 小的先画、y 大的盖在上面）——不是 XML 列表顺序！此前 stone_06/stone_05 重叠区「前后层反了」（官方 stone_06 盖 stone_05，工具相反），根因就是没按 y 排序。对象层 XML 有 `draworder="index"` 属性时才按列表顺序。修复后**强差异归零**（模板匹配 stone_06/stone_05 官方与工具均 0 差异）

**验证记录**（预览01 第 0 帧 vs 官方 tmxrasterizer）：
- 修复前（无对象层解析）：植物/角色完全缺失
- 左上对齐 + 原尺寸：差异 20479 点（全部对象偏 16px）
- 底部对齐修复：差异 3384 → 四舍五入修复后 621 点
- **topdown 排序修复（v4.1）：强差异 = 0，仅 477 点半透明 ±1 舍入弱差（正常基线）**

### 4.7 tmxrasterizer 交叉验证的坑（2026-09-17 实测）

1. **临时 tmx 必须放在 tiled 根目录内**（与 tmx 同级）：tmx 引用 `../project_end/...` 相对路径，复制到别处图片加载失败 → 渲染输出**纯红图**（不是报错），对比全绿失败。放 `_临时\` 也会失效，须放 tiled 根目录、用完即删
2. **tmx 必须 UTF-8 BOM 写入**（utf-8-sig），否则渲染器读乱码
3. **所有瓦片层 visible=0（只留对象层）会触发渲染器崩溃**（rc=1 无输出）——无法用官方直接出"纯对象层"参考图，隔离对比改用"全图对比 + 逐像素分类"定位
4. 对比结论判读：半透明边缘 ±1/255 舍入差正常；纯瓦片层预览01 与官方仅 314 点差异、预览02 386 点——这两个数就是各自的"舍入基线"
