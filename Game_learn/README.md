# Game_learn — 星露谷游戏系统解构学习包

> 目标：通过解剖一款成熟游戏（星露谷 1.6），建立"游戏创建之初该设计哪些东西"的系统框架思维。
> 你的身份：美术设计师，学 Godot，用 AI 辅助写代码。

---

## 📁 这套材料包含什么

| 文件 | 内容 | 建议阅读顺序 |
|---|---|---|
| `星露谷系统解构分析.md` | ★ 主文档：引擎解剖 + 15 个系统组 + 70+ 数据表映射 + 真实数据样本 | 1 |
| `星露谷系统全景.html` | 系统架构可视化图（五层设计法 × 系统地图 × 数据层） | 2（配主文档读） |
| `解包数据/` | 18 张核心数据表解包 JSON（星露谷真实数据层） | 3（按需打开对照） |
| `解包工具/` | 可复用 XNB 解包器源码 + 用法说明（想解包其他表时用） | 按需 |

另：配套上一轮的《游戏框架设计蓝图》（五层设计法）保存在聊天输出目录，可对照使用。

---

## 🧭 三遍读法（推荐）

**第一遍（30 分钟）**：读主文档第 0~3 节，只建立"星露谷有哪些系统"的整体印象。
**第二遍（1 小时）**：读主文档第 4~5 节 + 打开 2~3 个 JSON，观察"一个系统在数据层长什么样"。
**第三遍（动手）**：选一个你最想做的系统（种植/NPC/钓鱼…），
- 抄它的数据表字段 → 这就是你的"需求文档"
- 用五层蓝图为你的游戏画出同样的全景图
- 在 Godot 里按"系统 = Scene + Resource + 命名约定"搭骨架

---

## ⚠️ 使用注意

- 本材料仅用于个人学习分析，解包产物与游戏资产**不可商用、不可公开分发**。
- 解包数据是星露谷 1.6 的真实结构；老表（Fish/Quests 等）是紧凑字符串格式，新表（Objects/Crops/Machines 等）是结构化对象——两种风格并存，观察"框架演进"时很有价值。
