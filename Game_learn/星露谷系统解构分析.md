# 星露谷系统解构分析（学习版）

> 面向游戏框架设计学习者的解剖报告。基于 Steam 正版安装目录 `F:\steam\steamapps\common\Stardew Valley`（1.6.x）分析。
> 本文档帮助你回答一个问题：**"一个完整的模拟经营游戏，在大框架上到底由哪些系统组成？"**

---

## 0. 一句话结论

**星露谷是一个"数据驱动"的游戏。** 它的引擎代码（约 6MB 的 DLL）只负责"通用规则"（时间怎么走、物品怎么用、地图怎么渲染），而**游戏的全部内容——作物、NPC、任务、鱼、怪物、收集包——都是数据表**。

这对你意味着：**拆解星露谷 = 读它的数据表**。你不需要读懂代码，就能看懂它的系统设计。这正好印证了我们之前聊的框架蓝图：数据层是美术的主场。

---

## 1. 引擎与程序解剖（安装目录）

| 组成 | 文件 | 说明 |
|---|---|---|
| 引擎 | `MonoGame.Framework.dll` (2.1MB) | XNA 框架的继任者（C# 游戏框架），负责渲染、输入、音频 |
| 地图库 | `xTile.dll` | 瓦片地图（Tiled）渲染引擎 |
| 主程序 | `Stardew Valley.dll` (6MB) | 游戏逻辑（时间、NPC AI、农场模拟、存档……） |
| 数据模型 | `StardewValley.GameData.dll` | 1.6 新增：全部数据表的类型定义 |
| 联机 | `Galaxy64.dll`, `Lidgren.Network.dll` | 多人联机 |
| 运行时 | 大量 `System.*.dll` | .NET 8 运行时 |

**重要结论（回应你的最初问题）**：星露谷**不是 Unity 项目**，它用的是 C# + MonoGame + xTile。但这不影响学习价值——它的"内容组织方式"（数据表 + 资产目录）与引擎无关，任何引擎都适用。

游戏的全部内容在 **`Content` 文件夹**里，占整个游戏体量的大部分。

---

## 2. Content 目录：13 大类内容组织

```
Content/
├── Data/              ← 数据表（190 个文件）★ 系统设计的核心
├── Maps/              ← 地图（472 个文件，约 325 张地图）★
├── Characters/        ← NPC 角色贴图（125 个，含季节变体）
├── Portraits/         ← NPC 立绘头像（101 个）
├── Animals/           ← 农场动物贴图（43 个：鸡/牛/猪/羊/鸭…）
├── Buildings/         ← 建筑贴图（47 个：鸡舍/谷仓/温室/风车…）
├── TerrainFeatures/   ← 地形特征（38 个：耕地/草/树/蘑菇树…）
├── TileSheets/        ← 瓦片图集（41 个：作物/家具/地板/灌木…）
├── LooseSprites/      ← UI 与杂项精灵（147 个：光标/聊天框/表情…）
├── Strings/           ← 全部文本（372 个，×12 语言）+ NPC 日程
├── Minigames/         ← 小游戏（53 个：钓鱼判定/射箭/牌类…）
├── Effects/           ← 着色器效果（3 个）
├── XACT/              ← 音频（XNA 音频格式）
└── Fonts/             ← 多语言字体（50 个）
```

**关键洞察**：星露谷把"美术资产"和"游戏内容"分开管理：
- **贴图**（怎么画）→ `Characters`、`TerrainFeatures`、`TileSheets` 等
- **数据**（是什么、什么数值）→ `Data`
- **文本**（怎么说）→ `Strings`（全部可翻译）

这对美术极友好：**改外观不用碰逻辑，改数值不用碰代码。**

## 3. 系统清单：数据表 → 系统映射（核心章节）

把 `Data` 目录的约 70 个核心数据表（去掉 12 语言副本后）按系统归组：

### 系统 A：农业与种植（核心循环主力）
| 数据表 | 内容 |
|---|---|
| `Crops` | 所有作物：季节、生长天数、阶段、收获物、再生长 |
| `FruitTrees` | 果树：生长、季节果实 |
| `GiantCrops` | 巨型作物（南瓜/甜瓜/花椰菜） |
| `WildTrees` | 野生树木（橡树/枫树/松树） |
| `FarmAnimals` | 农场动物：种类、价格、产物 |
| `Fences` / `FloorsAndPaths` | 围栏、地板路径 |
| `TerrainFeatures`（资产） | 耕地状态（浇水/施肥的贴图） |

### 系统 B：物品与装备
| 数据表 | 内容 |
|---|---|
| `Objects` | ★ 最大表：约 800+ 种物品（ID/名称/类型/价格/可食用性…） |
| `BigCraftables` | 大型可制作物（洒水器/熔炉/箱子…） |
| `Furniture` | 家具 |
| `Weapons` / `Tools` / `Boots` / `Trinkets` | 武器、工具、靴子、饰品 |
| `hats` / `Shirts` / `Pants` | 帽子、上衣、裤子（换装系统） |
| `Buffs` | 增益效果 |

### 系统 C：机器与制作
| 数据表 | 内容 |
|---|---|
| `Machines` | ★ 机器规则引擎：输入→输出（骨碎机/熔炉/罐头机…） |
| `CraftingRecipes` | 制作配方 |
| `CookingRecipes` | 烹饪配方 |
| `TailoringRecipes` | 缝纫配方 |
| `BigCraftables` | 可制作的大型物件 |

### 系统 D：NPC 社交（叙事层）
| 数据表 | 内容 |
|---|---|
| `Characters`（资产） + `NPCGiftTastes` | ★ 每个 NPC 的礼物喜好（谁爱什么） |
| `Strings\schedules\` | ★ 每个 NPC 一份日程表（360 个文件：几点去哪、天气/季节变体） |
| `EngagementDialogue` / `ExtraDialogue` / `Weddings` | 求婚/额外对话/婚礼 |
| `HairData` / `MakeoverOutfits` | 发型、换装 |
| `IncomingPhoneCalls` | 来电对话（1.6 新增） |

### 系统 E：任务与进度
| 数据表 | 内容 |
|---|---|
| `Quests` | 主线/支线任务（类型/标题/描述/目标/地点） |
| `SpecialOrders` | 特殊订单（皮埃尔/罗宾的任务板） |
| `MonsterSlayerQuests` | 怪物猎人悬赏 |
| `SecretNotes` | 秘密纸条 |
| `Achievements` | 成就 |
| `MuseumRewards` | 博物馆捐赠奖励 |
| `LostItemsShop` | 失物招领 |

### 系统 F：战斗与冒险
| 数据表 | 内容 |
|---|---|
| `Monsters` | 怪物：HP/伤害/移动/掉落表 |
| `Weapons` / `Trinkets` / `Boots` / `Buffs` | 战斗装备与增益 |
| `Minecarts` | 矿车解锁站 |

### 系统 G：钓鱼
| 数据表 | 内容 |
|---|---|
| `Fish` | 鱼：价格/深度/时间/季节/天气/难度 |
| `AquariumFish` | 水族箱鱼 |
| `FishPondData` | 鱼塘繁殖 |

### 系统 H：经济与商店
| 数据表 | 内容 |
|---|---|
| `Shops` | 各商店的商品清单与售价 |
| `Concessions` / `ConcessionTastes` | 电影院小卖部（1.6） |
| `Objects.Price`（物品表内） | 卖出价 |
| `Bundles` | 社区中心收集包（详见系统 I） |

### 系统 I：社区与收集（长线目标）

### 系统 J：建筑与家园

### 系统 K：节日与电影（内容事件）

### 系统 L：地点与地图
| 数据表 | 内容 |
|---|---|
| `Maps`（资产，325+ 张） | 农场/小镇/海滩/沙漠/矿井… |
| `Locations` | 地点定义（名称/室内外/音乐…） |
| `LocationContexts` | 地点上下文（1.6） |
| `WorldMap` | 世界地图 |
| `VolcanoLayouts` | 火山层布局 |

### 系统 M：能力与触发器（1.6 新架构）
| 数据表 | 内容 |
|---|---|
| `TriggerActions` | ★ 通用触发器-动作系统（事件/条件/动作） |
| `Powers` | 玩家能力 |
| `AudioChanges` | 音频触发变更 |

### 系统 N：邮件
| 数据表 | 内容 |
|---|---|
| `mail` | 游戏内邮件（发件人/正文/附件） |

### 系统 O：本地化与文本（横切系统）

| `Fonts` | 多语言字体 |
| `SpeechBubbles` / `Lexicon` | 气泡文本、词汇 |

## 4. 数据层长什么样（解包样本）

我们用自制工具解包了 18 个核心表到 `解包数据/` 目录（JSON 格式），真实样本：

**① Objects（物品表，1.6 新结构化格式）**——物品 ID 0 = 杂草：
```json
"0": {
  "Name": "Weeds",
  "DisplayName": "[LocalizedText Strings\\Objects:Weeds_Name]",
  "Type": "Litter",
  "Category": -999,
  "Price": 0,
  "SpriteIndex": 0,
  "Edibility": -300,
  "CanBeGivenAsGift": true,
  "CanBeTrashed": true,
  ...
}
```
**观察**：物品的"显示名/描述"不直接写死，而是引用 `Strings\Objects` 里的本地化文本——这就是为什么游戏有 12 种语言。数值（价格、可食用性）与显示（名字、贴图）彻底分离。

**② Crops（作物表，1.6 结构化格式）**——作物 ID 472（防风草）：
```json
"472": {
  "Seasons": [0],           // 春季
  "DaysInPhase": [1,1,1,1], // 4 个生长阶段各 1 天
  "RegrowDays": -1,         // 不再次生长
  "HarvestItemId": "24",    // 收获物 = 物品 24
  "HarvestMinStack": 1,
  "Texture": "TileSheets\\crops",  // 贴图引用
  "SpriteIndex": 0
}
```
**观察**：作物完全由数据定义——贴图、生长天数、收获物全部可改。

**③ Fish（鱼表，老式字符串格式）**——ID 128 = 河豚：
```
Pufferfish/80/floater/1/36/1200 1600/summer/sunny/690 .4 685 .1/4/.3/.5/0/true
名称/价格/泳姿/深度/尺寸/出现时间/季节/天气/掉落物/难度/…
```
**观察**：老表用"斜杠分隔字符串"（紧凑但难读），新表用结构化对象。两种风格并存是 1.6 重构的痕迹。

**④ Bundles（收集包）**：
```
Pantry/0: Spring Crops/O 465 20/24 1 0 188 1 0 .../...
房间/序号: 主题/奖励/所需物品列表/...
```

## 5. 对照框架蓝图：星露谷怎么回答"该设计哪些东西"

把我们之前画的五层蓝图套到星露谷上：

| 蓝图层级 | 星露谷的答案 |
|---|---|
| ① 游戏支柱 | "逃离城市压力，慢慢经营小镇生活"（经营成长 + 田园治愈 + 自由节奏） |
| ② 核心循环 | 种→收→卖→升级/解锁→种更多（1~5 分钟闭环） |
| ③ 系统清单 | 上文系统 A~O（农业/物品/NPC/任务/战斗/钓鱼/经济/建筑…） |
| ④ 系统依赖 | 种植→经济→升级→解锁更多；NPC 好感→剧情→新内容；钓鱼→收集→博物馆… |
| ⑤ 数据层 | Data 目录 70+ 张表（正是你解包看到的这些 JSON） |

**给你的三个学习杠杆**：
1. **数据表 = 系统的"需求文档"**。看 `Crops` 表就能还原"种植系统需要哪些功能"。
2. **观察新老格式并存**（Fish 字符串式 vs Objects 对象式）——这就是"框架演进"的活教材：老系统用紧凑格式，新系统用可扩展结构。
3. **美术资产命名规律**（`tree1_spring/summer/fall/winter`、`Abigail_Beach`）告诉你：**季节系统、服装系统都靠"命名约定"驱动**——这是美术可以直接参与设计的部分。

## 6. 下一步建议（Godot 学习路线）

这套材料 + 蓝图模板，建议按以下顺序用：

1. **读本文档第 3 节**，选 3 个你最感兴趣的系统（比如种植、NPC、钓鱼）
2. **打开对应 JSON**，看真实数据结构，试着自己画出"如果我做，这个系统要哪些字段"
3. **对照蓝图模板**，为你的游戏填出 5 层框架
4. 在 Godot 里用空场景搭系统骨架（参考第 3 节的分组）
